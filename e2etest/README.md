# API E2Eテスト

`../docs/openapi.yaml`をAPI契約として、起動済みサーバーへHTTPリクエストを送信します。
契約検証に加え、書き込み後の取得やユーザー間の分離を検証します。
clientと共通のTypeScript workspaceに属し、サーバー・DB・フロントエンドの実装は参照しません。

## 実行

Node.jsとpnpmのバージョンは[ルートの開発環境](../README.md)に従います。インストールはリポジトリルートで実行します。

```sh
pnpm install --frozen-lockfile
cd e2etest
pnpm check:api
pnpm typecheck
pnpm lint
pnpm fmt:check
pnpm test:unit
E2E_BASE_URL=http://localhost:8080 pnpm test
```

ルートからは`pnpm test`でclientと検証器のユニットテスト、
`E2E_BASE_URL=http://localhost:8080 pnpm test:e2e`でE2Eを実行できます。
共通依存のバージョンはルートのcatalog、TypeScript設定は`tsconfig.base.json`、fmt・lintはルートのOxfmt・Oxlint設定を使用します。
`pnpm fmt`で整形できます。生成型はfmt・lint対象外です。

`E2E_BASE_URL`は必須です。未指定・不正な場合、通信前に失敗します。
パス接頭辞が必要な環境では `http://localhost:8080/api` のように指定できます。
接頭辞を自動で補うことはありません。

接続先には破棄可能なテスト環境を指定してください。登録・問題作成・更新・削除・解答も送信します。
テストからサーバーやDBを起動・停止・初期化することはありません。
振る舞いテストは作成した問題を所有ユーザーとしてfinallyで削除します。既に削除済みの404は許容します。
失敗時も後片付けを試み、元の失敗理由を保持して後片付けの失敗も報告します。
契約テストの作成データと、削除APIのないユーザー・解答は完全に回収できません。
環境の破棄・初期化は実行者が行ってください。

## 契約テストの検証範囲

- 全12操作を、任意クエリの有無を含む14ケースで逐次実行します。操作の追加・削除によるケースとの不一致も検出します。
- 送信前に全ケースのボディとクエリをスキーマ検証します。文字列の識別子は実行ごとに生成し、独立ケースで指定する数値IDは `-1` とします。
- 受信ステータス、Content-Type、JSON構文、プロパティの型と日時などの形式を検証します。JSONのContent-Typeにはcharset指定を許容します。
- 仕様に定義された403・404も適合とします。すべてのステータス分岐を発生させるテストではありません。
- プロパティに必須指定がなければ欠落を許容し、追加プロパティも仕様で禁止されていなければ許容します。レスポンスボディが未定義の場合、ボディやContent-Typeには条件を追加しません。
- 認証ヘッダー・Cookieの保存や送信はしません。登録とログインには同じ生成済み入力を使用しますが、レスポンスのtokenやIDを他の操作に引き継ぎません。
- 得点、並び順、フラグ非公開、操作の成功、データの永続化など、スキーマが保証していない条件は検証しません。現実装との差は失敗として報告し、期待値を緩和しません。
- リクエストはボディ受信まで10秒でタイムアウトします。リダイレクト追従と再試行は行いません。

契約検証器は現在のOpenAPI 3.0スキーマで使われるJSON、クエリ、型・形式に対応します。
今後、別のメディアタイプやパラメーター位置などを仕様へ追加する際は、ケースと検証器の対応も更新してください。

## 振る舞いテストの検証範囲

`test/behavior.e2e.test.ts`に、計画のB01〜B21に対応する50ケースを実装しています。
各テストは必要なユーザーと問題を独立して作成し、返されたIDとtokenを後続の操作へ渡します。

- descriptionの11種類の文字列（引用符、バックスラッシュ、改行・タブ、文字としての `\\n`、日本語・絵文字、空文字など）について、作成応答と公開・個人一覧の取得値が完全一致すること。
- 複数問題のIDと内容が混ざらず、更新・削除が後続GETに反映され、他の問題を変更しないこと。
- 公開問題にflagがなく、作成者の一覧には入力どおりのflagがあること。
- 正解・不正解、特殊文字を含むflagとanswer、flag更新後の判定、問題ごとの履歴絞り込みが正しいこと。
- 自作問題への解答と重複提出が成功し、公開履歴にanswerやflagが含まれないこと。
- 別ユーザーの更新・削除が403となり状態が変わらず、個人用一覧・履歴に他人のデータが混ざらないこと。
- 削除済みIDへの更新・再削除・解答が404となり、問題が復活しないこと。
- SQLインジェクションを模した5種類の文字列をname・description・genre・flagへ個別に入力し、POST/PUT後にそのまま取得でき、別の問題が変化しないこと（20ケース）。
- 同じ5種類の文字列をanswerとして提出し、flagと一致する場合だけ正解となり、個人履歴にそのまま残り、公開履歴にも判定が反映されること（5ケース）。

SQL風の入力には引用符を使うOR条件、UNION、セミコロンで区切ったDELETE文、バックスラッシュとコメントを含めます。
これらはAPIへ送るテストデータであり、テストコードからSQLを直接実行しません。
認証入力や全SQL構文を網羅するものではなく、これらのケースの成功だけでSQLインジェクション全般への耐性を保証するものではありません。

要求と応答には共通の契約検証を適用し、シナリオごとに期待するステータスと値も検証します。
必要なID・token・判定結果が欠落する場合は失敗とし、未実装や接続失敗をskipしません。
認証は既存の開発方針に従う暫定的なBearer方式です。OpenAPIには認証方式が未記載のため、最終仕様に合わせて共通クライアントを更新してください。
401・ログアウト後の失効、配点、重複提出の履歴件数、削除後の履歴保持は仕様確定後の追加対象です。

一覧全体の件数や順序、固定ID、DBの実装に依存しません。
リクエストは10秒、複数リクエストと後片付けを含む各シナリオは360秒で打ち切ります。
ファイル・シナリオは逐次実行し、反映待ちのsleep、ポーリング、書き込みの再送は行いません。
これは別HTTPリクエストでの状態確認であり、プロセス再起動をまたぐ永続性やブラウザー表示のテストではありません。

ルートの `pnpm test:e2e` は契約・振る舞いの両スイートを実行します。
個別に実行する場合は `e2etest/` で次を使用できます。

```sh
E2E_BASE_URL=http://localhost:8080 pnpm exec vitest run test/behavior.e2e.test.ts
E2E_BASE_URL=http://localhost:8080 pnpm exec vitest run test/contract.e2e.test.ts
```

## スキーマ変更時

```sh
pnpm generate:api
pnpm check:api
pnpm typecheck
pnpm test:unit
```

生成型は `src/generated/schema.ts` に保存します。手編集せず、OpenAPIから再生成してください。
実行時の期待値は毎回OpenAPIから読み込みます。型生成や検証のためにOpenAPIをコピー・改変しません。

`pnpm test:unit`はHTTP通信なしで、実際のOpenAPIを使って検証器の受理・拒否を確認します。
共有クライアントの送信内容、ステータス検証、応答本文読み取り時の失敗、必須値検証も、通信を差し替えたユニットテストで確認します。
E2E失敗時には操作・実ステータス・検証箇所を表示します。接続失敗と契約違反は区別されます。
